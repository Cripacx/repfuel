## Microcopy

Copy carries as much weight as layout. Same form, different words, different conversion.

- **Buttons name the reward, not the mechanic.** "Create my free account" feels like a gift; "Submit" feels like a chore — identical action.
- **Turn errors into help.** "Invalid input" tells the user nothing; "That email's taken — want to log in?" names the problem and offers the next move.
- **Empty states are onboarding**, not dead ends: show the first step available right now.
- **Placeholder text is not a label.** It vanishes on typing and leaves fields unidentified. Keep a persistent label above the input.
- **Write like a person.** No real human says "operation failed" — match the tone a helpful colleague would use.

## Empty States

- A blank screen reads as broken — users can't tell "nothing here yet" from a real failure. One small illustration or icon signals it's intentional.
- **Every empty state needs a primary action** — not "Try refreshing", but the next real step ("+ New project").
- **There are four kinds of empty**, each deserving its own copy and CTA:
  1. **First run** — nothing created yet
  2. **No results** — search returned nothing
  3. **Error** — the fetch failed
  4. **Filtered out** — the data exists but filters hide it
  Shipping one generic screen for all four is the common mistake.
- **The best onboarding moment you have**: show a ghost preview of what a real item will look like, teaching the feature before users touch it.
- Avoid cold, log-file copy ("ERROR 404 — Result set empty").

## Serial Position

Recall is **U-shaped**: people remember the first items (primacy) and the last (recency), and forget the middle.

- Treat the first and last slots as **bookends** for your highest-value content.
- **Navbars**: logo leads (primacy), primary CTA closes (recency); secondary links sit in the forgettable middle.
- **Landing pages**: open with the strongest USP, end with the strongest proof — testimonials, metrics, guarantees.
- **Onboarding**: the first slide hooks, the last delivers the payoff; middle steps carry setup nobody recalls verbatim.
- Item order is a design decision. Anything important dropped into the low-recall middle quietly loses impact.

## Landing Page Skeleton

Five sections, fixed order: **Hero → Proof → Problem → Solution → CTA.**

1. **Hero** answers three questions in ~3 seconds: *what* you offer, *who* it's for, *why* they should care. Headline + subhead + one CTA, nothing more. No carousels — they hide the one message that matters.
2. **Proof directly after the hero**, not buried at the bottom. Visitors decide whether to trust you almost immediately: logos, one testimonial, one hard number.
3. **Problem** — agitate before pitching. No felt pain means no reason to care about the cure. Name the real cost in time, money and frustration.
4. **Solution** — sell outcomes, not features. Cap at three benefits, each framed as a result: "save 10 hours a week" beats "advanced automation".
5. **CTA** — repeat the *exact same* call to action from the top: same color, same copy. Repetition converts the scroller who wasn't ready the first time.
